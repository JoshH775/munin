# munin

A personal second brain: a Discord bot on a private server for life stuff, covering memory, recall, reminders and check-ins. Named for Odin's raven Muninn, who flies out over the world daily and reports back; that daily-sweep-and-report is the product. It chats and remembers only. Work execution belongs to Claude Code sessions, never this bot. It runs open models on a personal DeepInfra key, kept separate from any work account.

## Architecture

- Channel = life domain (#cooking, #goals). `channel_settings` holds one row per channel with `muted` (per-channel, no inheritance), `ephemeral`, and `last_encoded_at` (the encoder's watermark). App-wide `chat_model` and `effort` live in the `app_settings` singleton, edited at runtime via `/config`. The persona lives in `system.md`, read at startup in `messageHandler`. A missing settings row means unmuted and non-ephemeral (zero setup); `ephemeral` inherits from the parent channel for threads, and messages in threads resolve to the parent channel's row.
- Memory: `semantic_memory` holds one row per channel or thread, a living `content` doc the encoder rewrites in full plus a one-line `description` of what the channel covers. `global_memory` is a singleton read into every prompt, and nothing writes it yet. `resolveMemory` tiers global + parent + own into the `<memory>` block. The chat model has no memory tools. The encoder writes everything, so `system.md` has the model say a thing is "noted", never "saved".
- Encoding: `sweepMemoryJob` (minute cron, `src/jobHandlers.ts`) asks `getChannelsToEncode` for channels whose unencoded chat has been quiet for 30 minutes, muted ones included since mute only stops replies, then calls `encodeChannel` (`src/ai/encode.ts`, prompt `src/ai/encode.md`). That's one DeepSeek-V4.1-Flash call, retried once on GLM-5.2, replying with `<memory>` and `<description>` or `NO_CHANGE`. The watermark moves to the last message read, on NO_CHANGE too. A failure saves nothing and backs the channel off for an hour, so no message is lost. Ephemeral channels are encoded like any other, and `sweepEphemeral` clears their messages at 4am London, skipping a channel while any of its chat is still unencoded.
- Memory is runtime state, so it lives in the DB. Prompts (`system.md`, `src/ai/*.md`) are files read at startup.
- `src/ai/index.ts` `turn()` is the agentic loop: one user message in, rounds of tool calls, one final text out. Tools are `makeTool()` objects, grouped by file in `src/ai/tools/`, and the turn ends when the model stops calling them. Every call is logged to `tool_log`. Before a reply goes out, `verify` (prompt `src/ai/verifier.md`, a model from another family) fact-checks it against the turn; a failed check regenerates once, then sends with a caveat.
- Exfil guardrail (the "lethal trifecta" of private data, untrusted content, and a way out). `makeTool` objects can carry `readsUntrusted` (pulls attacker-controllable content into context) and `arbitraryOutreach` (can send data to a destination the model chooses). Once a turn runs a `readsUntrusted` tool, `executeTool` refuses every `arbitraryOutreach` tool for the rest of that turn. Separately, `web_extract` is provenance-gated: it opens only URLs that arrived from a `web_search` result earlier in the same turn or from a user's own message (seeded in `messageHandler` via `findUrls`, matched after normalising), so a poisoned page can't steer it to an attacker URL. Tagging rule for new tools: a sensitive or untrusted read gets `readsUntrusted`, an action whose destination the model picks gets `arbitraryOutreach`, and a scoped tool with a fixed base URL and a server-side token gets neither.
- SQL-first migrations: plain `.sql` files in `src/db/migrations` (create via `pnpm db:migration <name>`), applied by `scripts/migrate.ts` against whatever `DATABASE_URL` the local `.env` supplies. Only `db:reset` runs the seed.
- Planned, not yet built: a nightly consolidate that lifts general facts from channel docs into `global_memory` and prunes dead weight; every channel's `description` as an index in the prompt, with `read_memory` back to open another channel's doc; check-ins.

## Dev vs prod

Same VPS, separated by directory. This checkout is dev: Postgres on 5434 from `docker-compose.dev.yml`. Prod is a clone at `/srv/munin`: Postgres on 20132 from `docker-compose.yml` (port scheme: `~/PORTS.md`). One Discord bot serves both, so running dev while prod is up gets duplicate replies. Stop one first. Deploying is `pnpm ship` (`scripts/deploy.sh`), which pulls into `/srv/munin`, migrates and restarts. Because that deploy pulls from the remote, a commit only ships once it's on the remote, so when a commit is made specifically to ship, push it after committing (ordinary commits Josh reviews in the working tree and don't need pushing). Prod is touched only from that directory, deliberately. Everything run from here stays on dev.

Debugging prod data: its Postgres is on `localhost:20132` (database and user both `postgres`), and the full `DATABASE_URL` with the password lives in `/srv/munin/.env`. Connect with `export $(grep '^DATABASE_URL=' /srv/munin/.env)` then `psql "$DATABASE_URL"`. Keep prod DB access read-only, SELECTs only, unless Josh explicitly asks for a write.

## Conventions

- tsx runs everything; imports are extensionless (bundler resolution), so plain `node` cannot run this code.
- Every model runs on DeepInfra through its OpenAI-compatible endpoint (`client`, exported from `src/ai/index.ts`). The chat model and effort come from `app_settings`; the encoder and verifier hardcode their own models.
- Times are Dayjs end to end, never `Date` or bare strings. `src/time.ts` names the zone (Europe/London) and parses model-supplied times; `src/db/index.ts` makes pg return `timestamptz` as Dayjs, serialises Dayjs on the way in, and refuses to boot if that parser is missing; kysely-codegen types those columns as Dayjs through the one-line `typeMapping` in `.kysely-codegenrc.json`, using an inline `import('dayjs').Dayjs` so no import has to be generated.
- `evals/` is gitignored: a local prompt-eval runner (`pnpm tsx evals/run.ts`) over private transcripts, kept in `tsconfig.json` so it still typechecks.
